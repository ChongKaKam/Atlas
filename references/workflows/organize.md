# ORGANIZE

基于已经存在的检索/维护问题整理。先读 [Review 与 Apply](../review-apply.md)。

1. 清点目标目录、overview、inbound/outbound links、重名和孤立候选；记录用户希望改善的具体问题。
2. 区分：命名/路径调整、重复 KU 合并、独立 KU 拆分、项目知识提升、overview 补充。工具的重名或 orphan 警告只是线索。
3. 提出最小路径映射和内容去向。跨领域选主要问题；不要为少量文件建立多层目录，不按 tags 批量移动。
4. 项目/领域笔记提升到 shared 时先保留实验条件与项目局部决定，按 [共享审核](../scopes.md) 给出具体泛化草案和原文去向；用户审核后才写 shared 并按批准方案改为链接。不能把局部测量推广成通用性能结论。内容重组使用 [Knowledge Capture](../../assets/knowledge-capture-prompt.md)，不以整理为由丢弃参数、步骤或案例。
5. 移动前搜 inbound links；移动后重新计算该文档所有 outbound relative links（含 Sources 和 assets）。修复引用式链接和 title anchors。全库重名不一定需要改名，但同目录大小写碰撞必须消除。
6. 删除/合并目标需要可核对的去向与相应授权；确有外部依赖才保留说明性 stub。不得自动删除 orphan。
7. 检查相对链接、结构与差异。若用户要求更新 INDEX，重新生成并审阅；避免为每次整理强制建立索引。
