# AUDIT

默认只读。先阅读 [工具说明](../tooling.md)，在明确的目标库运行 `audit`。使用目标 Python 环境，不假设当前目录就是 Skill 安装路径。

确定性检查覆盖 Frontmatter、H1、tags、链接存在性、重名、case collision、粗略格式和无 inbound links 的候选。旧库没有 Atlas schema 时报告兼容性差异；不自动补齐日期或状态。

再进行语义审阅：

- 抽样或全量范围须说明，检查主要 reader question 是否清晰、是否遗漏上下文。
- 查重名和相似段落，判断是否真正同一 KU；source lists 的相同不能证明知识重复。
- 识别来源薄弱、重要结论未限定、draft/deprecated 被当成现行事实、冲突被掩盖的地方。
- 检查 overview/README 是否提供合理入口；orphan 可能是有意独立笔记，并非应删除内容。

输出按“明确错误 / 需要语义审查 / 改进建议”分类，附文件位置、影响、建议修复和置信限制。没有执行的命令不能计为通过；工具没有验证的外部 URL、技术真实性、人类审查事件需明确。

用户同时要求修复时，先处理授权范围内可确定的格式和断链；纠错、合并、删除按对应工作流判断。复查仅比较相关结果，避免把先前问题算成本轮新问题。
